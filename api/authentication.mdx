# Authentication

The updates.page API lets you create, publish, and manage posts programmatically.

<Note>
  API access is available on the **Pro** plan and above, and for the first
  **14 days** of any new account on the Free plan — so you can publish from a
  script, CI or an agent before you pick a plan.

  The trial starts when the account is created and isn't extended. When it
  ends, a Free account's keys stop working: existing keys aren't deleted, and
  they start working again as soon as the account upgrades. Keys also stop
  working if a paid account drops back to Free.
</Note>

## Base URL

All API requests are made to:

```
https://app.updates.page
```

All endpoints accept and return JSON.

## Creating an API key

<Steps>
  <Step title="Go to API Keys">
    In the dashboard, navigate to **Settings → Developer → API Keys**
  </Step>
  <Step title="Create a key">
    Give it a descriptive name, and optionally an expiry
  </Step>
  <Step title="Copy the key">
    The token is shown once, at creation. Store it somewhere safe
  </Step>
</Steps>

<Warning>
  Treat API keys like passwords. Don't commit them to source control or expose them in client-side code.
</Warning>

### Machine keys

Keys created for CI, scripts, and agents are **machine keys** by default. A machine key can reach the content API — posts, categories, uploads, and imports — and nothing else. It can't touch account settings, billing, the team, or mint further API keys, so a leaked CI token stays contained.

Turn the toggle off if you need a key with full account access.

### Expiry

A key can be given a lifetime of up to **one year**, or left with no expiry.

Separately, **a key that goes unused for 90 days stops working.** If a rarely-run job starts returning `401`, create a fresh key.

## Using your API key

Send your key in the `Authorization` header as a Bearer token:

```bash
curl https://app.updates.page/api/v1/posts \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Tip>
  Prefer not to manage keys by hand? The [CLI](/cli/overview) signs in through your browser and stores its own token.
</Tip>

## Errors

Failures return a JSON body with an `error` (or `errors`) field:

```json
{ "error": "Invalid or expired API key" }
```

| Status | Meaning |
|--------|---------|
| `401` | Missing, revoked, expired, or stale key |
| `403` | Plan doesn't include API access, or the key isn't allowed here |
| `404` | No such record on your account |
| `422` | Validation failed — check the `errors` object |
| `429` | Rate limited |

## Rate limits

API requests are limited to **300 requests per 5 minutes** per IP.
